# Казино-зал без денег: Краш + Покер на кубиках

Мультиплеер для друзей (3+ человек), виртуальные фишки, соревнование друг с другом. Запуск локально, друзья заходят по ссылке через cloudflared.

## 1. Принципы

- Никаких реальных денег. Только фишки, у всех одинаковый старт (1000).
- Сервер авторитетный: вся случайность и все расчёты на сервере. Клиент только рисует и шлёт команды ("поставить", "забрать", "сбросить").
- Один общий баланс фишек на игрока, он работает во всех играх зала.
- Фишки, внесённые за покерный стол (бай-ин), замораживаются: их нельзя тратить в Краше, пока игрок сидит за столом. При уходе со стола остаток возвращается в баланс.
- Рейтинг: таблица лидеров по капиталу (баланс + фишки на столе).
- Если фишки кончились: раз в сутки "пособие" 200 фишек, чтобы никто не вылетал навсегда. Условие: капитал (баланс + фишки на столе + активная ставка в Краше) < 10.

## 2. Стек (минимум зависимостей, без сборки)

- Node.js 20+
- `express` (раздача статики) + `ws` (WebSocket)
- Клиент: обычный HTML + CSS + JS (vanilla), без фреймворков и сборщиков
- Хранение: JSON-файл `data/players.json` (балансы). База не нужна.

## 4. Протокол (WebSocket, JSON)

Каждое сообщение: `{ "type": "...", ...поля }`.

Клиент -> сервер:
- `hello` { token } или { name } : вход по токену или регистрация; сервер отвечает `welcome`
- `claim_bonus` {} : суточное пособие
- `crash_bet` { amount, autoCashout? }
- `crash_cashout` {}
- `poker_join` { buyIn } / `poker_leave`
- `poker_action` { action: "check" | "bet" | "call" | "raise" | "fold", amount? }
- `poker_reroll` { keep: [bool x5] }
- `chat` { text }

Сервер -> клиент:
- `welcome` { playerId, token, name, balance }
- `online` { players: [ { id, name } ] }
- `balance` { balance, reserved, bonus: { amount, eligible, availableIn } } : reserved = фишки в играх
- `leaderboard` { players: [ { id, name, capital, online } ] }
- `crash_state` { phase: "betting" | "running" | "crashed", multiplier, endsAt?, players: [...] }
- `poker_state` { phase, pot, players (свои кубики видны только тебе), turn, dealer, turnEndsAt, ... }
- `error` { message, code? } : code `bad_token` (токен не найден, показать вход), `bad_name`

Имена уникальны без учёта регистра. Токен отдаётся только владельцу и не попадает в рейтинг.

Важно: чужие кубики в `poker_state` не отправлять до вскрытия.

## 5. Игра 1: Краш

Цикл раунда (на сервере, один общий стол):
1. `betting` (8 сек): игроки ставят фишки.
2. `running`: множитель растёт, сервер шлёт `crash_state` ~10 раз в секунду.
3. Игрок жмёт "забрать": выигрыш = ставка x текущий множитель, начисляется сразу.
4. В момент краха все, кто не забрал, теряют ставку. Пауза 4 сек, новый раунд.

Математика:
- Точку краха сервер выбирает ДО старта раунда: `r = случайное число [0,1)`, `crashPoint = max(1.00, floor(99 / (1 - r)) / 100)`, верхний предел x100.
- Эта формула даёт казино преимущество 1%: P(краш >= x) = 0.99 / x, около 2% раундов крашатся сразу на x1.00. В среднем фишки у всех медленно тают. Это осознанный выбор (иначе нет стимула вовремя забирать). Если захочется честной игры, заменить на `floor(100 / (1 - r)) / 100`.
- Рост множителя: `m(t) = exp(0.07 * t)`, где t в секундах с начала фазы `running`. Краш наступает, когда `m(t) >= crashPoint`.
- Клиент не считает исход, только показывает присланный множитель (можно сглаживать анимацию между пакетами).
- Автовывод: опциональное поле "забрать автоматически на xN" (сервер сам исполняет).

Правила ставок: минимум 10, максимум = свободный баланс (без фишек на покерном столе). Одна ставка на раунд на игрока (в MVP). Ставка списывается сразу при приёме.

## 6. Игра 2: Покер на кубиках

Для 2-6 игроков за столом.

Посадка:
- `poker_join { buyIn }`: бай-ин от 50 до свободного баланса. Фишки переходят из баланса в стек за столом.
- Если стек стал меньше анте (10), игрок пропускает раздачи, пока не докупится или не встанет.
- `poker_leave` между раздачами: стек возвращается в баланс. Посреди раздачи: игрок сбрасывает карты (fold), стек возвращается после окончания раздачи.
- Новая раздача стартует автоматически через 5 сек после предыдущей, если за столом ≥ 2 игроков со стеком ≥ анте.

Раздача:
1. Анте: каждый вносит 10 фишек в банк.
2. Каждый получает 5 кубиков, видит только свои.
3. Круг ставок 1: check / bet / call / raise / fold.
4. Перебросок: каждый выбирает, какие кубики оставить, остальные перебрасываются (один раз). Все делают это одновременно, таймер 30 сек (по истечении: ничего не перебрасывать).
5. Круг ставок 2.
6. Вскрытие: сильнейшая комбинация забирает банк. При равенстве делят (остаток от деления получает первый после дилера).

Если все кроме одного сбросили, оставшийся забирает банк без вскрытия.

Порядок ходов:
- Дилерская кнопка сдвигается на одно место по кругу каждую раздачу.
- В каждом круге ставок первым ходит первый активный игрок после дилера.
- Круг ставок заканчивается, когда все активные игроки сделали ход и их вклады в этом круге равны (или остался один игрок).
- Ставки: bet/raise минимум 10, кратно целому. В MVP максимум 3 повышения за круг.

Комбинации (от сильной к слабой):
1. Пять одинаковых
2. Каре (4 одинаковых)
3. Фулл-хаус (3 + 2)
4. Стрит (большой 2-3-4-5-6 > малый 1-2-3-4-5)
5. Сет (3 одинаковых)
6. Две пары
7. Пара
8. Старшая карта (сравнение по значениям по убыванию)

Сравнение внутри одной комбинации: по значению (каре шестёрок > каре пятёрок), затем по кикеру.

Реализация: функция `evaluate(dice) -> { rank, tiebreakers[] }` и функция `compare(a, b)`. Обязательно написать для них тесты (простые `node:test`).

Ограничения MVP: без all-in и side pots (ставка не может превышать наименьший стек среди активных игроков в раздаче), таймер на ход 30 сек (по истечении: check, если возможно, иначе fold).

Отключение: разрыв соединения сам по себе не сбрасывает карты. Ход отключившегося истекает по обычному таймеру. Если игрок не вернулся к концу раздачи, после неё он встаёт из-за стола, стек возвращается в баланс.

## 7. Этапы (делать строго по порядку)

**Этап 0: скелет и туннель (30 минут)**
- `npm init`, поставить `express` и `ws`.
- Сервер раздаёт `public/` и принимает WebSocket.
- Клиент подключается, шлёт `hello`, получает `welcome`.
- Проверить локально, затем через cloudflared (см. раздел 8) открыть с телефона/у друга.
- Готово, когда: два человека видят друг друга в списке "онлайн".

**Этап 1: игроки и баланс**
- Токен в `localStorage`, повторный вход возвращает того же игрока.

- Лидерборд, пособие раз в сутки.
- Готово, когда: перезапуск сервера не сбрасывает фишки.

**Этап 2: Краш**
- `server/crash.js` с циклом раундов, клиент с графиком/числом множителя, кнопками "ставка" и "забрать".
- Список ставок остальных игроков в реальном времени.
- Готово, когда: трое играют несколько раундов подряд, балансы сходятся.

**Этап 3: Покер на кубиках**
- Сначала `dicepoker.js` с `evaluate` и тестами, потом стол, потом UI.
- Готово, когда: полная партия на 3 человек от анте до вскрытия без зависаний.

**Этап 4: шлифовка**
- Реконнект (вернулся в стол после обновления страницы), чат, звуки, анимации кубиков.
- Защита: лимит частоты сообщений, проверка всех входных данных на сервере.

## 8. Запуск через cloudflared

```
node server/index.js                              # порт 3000
cloudflared tunnel --url http://localhost:3000    # даёт ссылку *.trycloudflare.com
```

- Ссылка меняется при каждом запуске. Для постоянной нужен именованный туннель.
- Клиент должен подключаться к WebSocket относительно текущего адреса:
  `const ws = new WebSocket((location.protocol === 'https:' ? 'wss://' : 'ws://') + location.host)`
- Не хардкодить `localhost` в клиенте.

## 9. Типичные ошибки (заранее)

- Доверять клиенту сумму ставки или множитель. Всё проверять на сервере.
- Отправлять чужие кубики до вскрытия.
- Гонки: игрок жмёт "забрать" в тот же тик, когда произошёл краш. Решение: сервер обрабатывает сообщения в одном потоке и сравнивает с текущим состоянием раунда.
- Списывать ставку дважды при повторной отправке. Ставка идемпотентна: одна на раунд.
- Отрицательные и дробные суммы. Приводить к целому, проверять `> 0` и `<= balance`.
- Тратить в Краше фишки, которые лежат на покерном столе. Стек за столом отделён от баланса.
- Авто-fold сразу при отключении: обновление страницы не должно стоить раздачи. Ждать таймер хода.
